# 食品过敏原标签审查台

基于 **FastAPI + SQLite** 的食品过敏原标签审查工具：在浏览器中录入带嵌套子配料的配方文本和原料过敏原字典，系统自动解析括号层级、沿配料树传播并汇总每种原料的过敏原集合，与标签声明比对指出**遗漏 / 多报**的过敏原；支持录入**两版配方**查看过敏原变化，并可一键导出标签审查报告（HTML / Markdown）。

## 功能一览

- 🌳 **嵌套配方解析**：`巧克力酱（可可脂，奶粉（乳清粉，乳糖））` 多层括号任意嵌套，中英文括号均可
- 🧬 **过敏原传播**：子配料的过敏原自动向上传播到父级配料，逐层汇总
- 🔎 **遗漏来源追踪**：每个遗漏过敏原保留其在嵌套配料树中的全部来源路径（如 `巧克力酱 › 奶粉 › 乳清粉`），同名原料出现在不同分支时路径分别保留、稳定去重排序；结果页可逐项展开，HTML / Markdown 报告同步输出，升级前的历史记录重新打开时也会自动补齐
- ✅ **标签核对**：对照标签声明的过敏原，标出「遗漏（必须补充）」「多报」「一致」
- 🔄 **版本对比**：录入现版 / 新版两版配方，输出新增、减少的过敏原及每种配料的变化
- 📄 **报告导出**：HTML（可直接打印存档）与 Markdown 两种格式
- 📚 **字典管理**：原料 → 过敏原字典批量导入、逐条增删，未登记原料自动提示
- 🕰️ **字典时效复核**：每次审查保存所用字典（仅限配方实际涉及原料）的稳定指纹；字典增删 / 批量导入后，仅当记录配方涉及的原料映射发生变化时，历史列表才标出「需复核」（顺序调整、无关原料变化、把未识别原料补登为空均不误报）；历史详情可一键复核，先展示遗漏 / 多报 / 来源路径的前后差异，确认后覆盖结果并更新指纹；无指纹的旧记录按需复核
- 💾 **持久化**：SQLite 存储字典与全部历史审查记录，可随时回看、重新导出

## 快速开始

### 方式一：Docker Compose（推荐）


## 使用说明

1. **导入过敏原字典**：每行一条，格式 `原料名：过敏原1，过敏原2`（冒号、逗号中英文均可），例如：

   ```text
   小麦粉：麸质谷物
   乳清粉：乳
   大豆卵磷脂：大豆
   可可脂：
   ```

2. **录入配方**：配料用逗号分隔，括号表示子配料，可多层嵌套；`配料表：` 等前缀会自动去除：

   ```text
   配料表：小麦粉，白砂糖，巧克力酱（可可脂，奶粉（乳清粉，乳糖），大豆卵磷脂），鸡蛋，食盐
   ```

3. **勾选标签声明的过敏原**，点击「开始审查」，即可看到：
   - 标签核对结论（遗漏 / 多报 / 一致）；
   - 配方解析树，深绿色徽章为原料自身标注，浅色徽章为子配料传播结果；
   - 填写配方 B 时，额外展示两版过敏原差异与每种配料的变化。
4. **导出报告**：结果页或历史记录中下载 HTML / Markdown 审查报告。

页面上「填充示例」按钮可一键载入演示字典与两版配方，快速体验完整流程。

## 字典时效复核（历史记录）

过敏原字典更新后，旧审查的结论可能过时。系统用**作用域指纹**判断每条历史记录是否需要复核：

- 新建审查时，对**该记录 A/B 配方中实际出现过的原料**（含嵌套子配料与复合原料），按「原料 → 过敏原集合」的归一化映射排序后取 SHA-256 摘要，与记录一并保存；
- 字典发生增删、逐条修改或批量导入后，历史列表的「字典时效」列会重新比对：
  - ✅ **字典时效有效**：涉及原料的映射未变化；
  - ⚠️ **需复核**：涉及原料的过敏原映射已变化（列表行高亮）；
  - 指纹只看映射内容，因此**字典条目顺序调整、与配方无关原料的增删改、重复导入**都不会误报；把未识别原料补登为「无过敏原」条目（映射仍为空集）同样不会误报，只有赋予/增减过敏原才会；
  - 升级前产生、没有指纹的旧记录显示「需复核（旧记录）」，可按需复核。

**一键复核操作**：

1. 在历史列表点击「一键复核」，或打开历史详情后点击顶部黄色横幅中的按钮；
2. 系统用**当前字典**重新解析原始 A/B 配方与标签声明，页面先展示前后差异：
   - 标签遗漏 / 多报的新增与消除、声明一致项变化；
   - 每个遗漏过敏原在配料树中的**来源路径**新增与消失；
   - 各版配方过敏原全集、未识别原料及两版配料变化表是否改变；
   - 同时给出按当前字典重算的完整结果预览（此步**不写库**）；
3. 点击「确认覆盖并更新指纹」后，旧结果才被覆盖，并记录复核时间（`rechecked_at`）与新指纹；「取消」则保留原结果。

即使状态为「字典时效有效」，也可以在详情页点击「仍可手动重新复核」随时重算。导出的 HTML / Markdown 报告会附带字典指纹、最近复核时间，需复核时给出提示。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dict` | 获取过敏原字典 |
| POST | `/api/dict` | 新增 / 更新单条字典 |
| POST | `/api/dict/bulk` | 批量导入字典（`{"text": "..."}`） |
| DELETE | `/api/dict/{ingredient}` | 删除字典条目 |
| POST | `/api/reviews` | 创建审查（单版或两版配方 + 标签声明，自动保存字典指纹） |
| GET | `/api/reviews` / `/api/reviews/{id}` | 审查列表 / 详情（含 `needs_review`、`legacy`、`rechecked_at` 时效字段） |
| DELETE | `/api/reviews/{id}` | 删除审查记录 |
| GET | `/api/reviews/{id}/recheck` | 复核预览：当前字典重算结果 + 遗漏/多报/来源路径前后差异（不写库） |
| POST | `/api/reviews/{id}/recheck` | 确认复核：覆盖结果、更新字典指纹与复核时间 |
| GET | `/api/reviews/{id}/report?format=html\|md` | 导出审查报告 |

```text
└── static/
    └── index.html # 单页 Web 界面
tests/

├── test_persistence.py # 持久化与报告测试
└── test_recheck.py     # 字典指纹与时效复核测试
Dockerfile
docker-compose.yml
requirements.txt
```
